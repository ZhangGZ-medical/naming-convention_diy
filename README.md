# naming-convention_diy

一套可执行的**文件系统命名规范**：三段式 `<领域>-<用途>-<主题>-<版本/状态>`，配一个零依赖校验器。

解决的实际问题：目录和文件堆到几百个之后，"凭名字找不到东西"和"版本号裸接导致脚本误处理旧版"这两个毛病会同时发作。

---

## 核心设计

### 命名模板

```
<领域>-<用途>-<主题>-<版本/状态>.<扩展名>

med-761tel-ia-rev-v2.md              管线调研报告 第2版
res-chictr-stroke-lit-final.md       检索清单 定稿
grant-qilu-2026-94-dsgn-wip.md       技术路线 草稿
ai-dsh-plugin-survey-doc-final.md    插件调研 正式稿
ops-call-transcript-raw.md           通话转录 原始素材
```

### 领域前缀（7 类，按"交付对象与合规链"划分，不按技术手段）

| 前缀 | 含义 | 适用范围 |
|---|---|---|
| `med-` | 临床医学与神经科学 | 干细胞管线、脑卒中/ALS、影像处理、患者数据集、临床方案 |
| `res-` | 科研方法与文献产出 | 综述、Meta、文献检索与验证、实验设计、绘图方法 |
| `ai-` | AI 工具链与技能资产 | 技能开发发布、模型能力调研、自动化编排 |
| `grant-` | 基金与标书申报 | 项目申报书、技术路线、附件 |
| `pat-` | 专利与知识产权 | 交底书、权利要求、检索查新、法律状态 |
| `biz-` | 商业与投资决策 | 商业计划书、尽调、投资测算 |
| `ops-` | 个人事务与运行维护 | 行程、通话转录、时间管理、环境排障 |

**推论规则：脚本跟随它的服务对象，不跟随技术栈。** 图像处理脚本归 `med-`，不单设工具域；PDF OCR 服务于文献提取归 `res-`，服务于合同解析归 `ops-`。

### 用途中缀（9 类，可选但推荐）

`-lit-` 检索与证据｜`-rev-` 综述与调研｜`-dsgn-` 方案与设计｜`-data-` 数据与数据集｜`-fig-` 图与视觉｜`-doc-` 正式成稿｜`-sld-` 演示与汇报｜`-tool-` 脚本与工具｜`-raw-` 原始素材

### 后缀

| 类别 | 写法 | 规则 |
|---|---|---|
| 版本 | `-v1` `-v2` | **必须带短横线**，禁止 `xxx2` 裸接 |
| 状态 | `-wip` `-pre` `-final` `-arch` | 缺省视为 `-wip` |
| 日期 | `-YYYYMMDD` | 仅用于时间序列产物 |

## 两套独立规则（最易误读处）

| 对象 | 规则 |
|---|---|
| 文件 / 普通目录 | 三段式模板 **N1–N6** |
| **自建技能目录名** | 只受 **N7–N9**：须以 `_diy` 结尾、`-diy` 变体建议统一、`_diy` 不得在中段。**不要求领域前缀** |

**`_diy` 只用于标记自建技能**，用途是与上游/第三方技能区分开。它**不加**在普通文件、普通目录或代码标识符上。

---

## 规则清单

| 编号 | 规则 | 级别 |
|---|---|---|
| N1 | 领域前缀须在词表内 | 阻断 |
| N2 | 建议补用途中缀 | 建议 |
| N3 | 禁止裸版号，须 `-vN` | 阻断 |
| N4 | 状态后缀取值合法 | 建议 |
| N5 | 日期须 8 位紧凑、仅时间序列 | 建议 |
| N6 | 段间用 `-`，禁止空格 | 阻断 |
| N7 | 自建技能须以 `_diy` 结尾 | 阻断 |
| N8 | `-diy` 变体建议统一为 `_diy` | 建议 |
| N9 | `_diy` 只能作结尾标记 | 阻断 |

**豁免**：上游技能族（`lc-`/`sci-`/`ms-`）、第三方技能、生态保留名（`README.md`、`SKILL.md`、`package.json` 等）、依赖与构建目录、代码内部标识符、历史存量名称。

## 澄清是强制的

**为任何对象命名前必须先澄清。** 理由：名称四个字段里**没有一个能可靠推断**——

| 字段 | 可否推断 | 说明 |
|---|---|---|
| 领域前缀 | ❌ 不可靠 | 取决于交付对象与合规链，同一关键词跨场景归不同域 |
| 用途中缀 | ❌ | 取决于处理阶段 |
| 主题 | ❌ | 必须由使用者提供 |
| 版本 / 状态 | ❌ | 取决于当前进度 |

工具输出的"含领域推测"是**提问信号**，不是命名依据。完整规程见 [`references/clarification.md`](references/clarification.md)：三批提问、领域决策树、完成判据（五项全确定）。

## 校验器用法

纯 Python 标准库，**零第三方依赖**。

```bash
PY="python"
SK="<技能目录>/scripts/check_name.py"

# 单个名称校验
"$PY" "$SK" --name "med-761tel-ia-rev-v2.md"
"$PY" "$SK" --name "my-new-skill" --as-skill      # 按自建技能名校验（启用 N7–N9）

# 目录存量审计（只报告）
"$PY" "$SK" --scan "<待审计目录>" --out report.txt

# 技能库自建标记审计
"$PY" "$SK" --skills-root "<技能库根目录>" --out skills-audit.txt
```

**退出码**：`0` 合规（可能含建议级）｜`1` 存在阻断级偏离｜`2` 参数错误。

> **Windows 提示**：PowerShell 用 `>` 重定向 Python 的 UTF-8 输出会按控制台代码页解码，中文变乱码——一律用 `--out` 参数写文件。

**扩充词表**：改 `references/scheme.md` 里的 `vocab-domain` / `vocab-kind` / `vocab-status` 代码块即可，**不需要改脚本**。

## 违规处理

| 级别 | 对象 | 动作 |
|---|---|---|
| **P0 阻断** | 本次新建的文件/目录/技能 | 定名前修正，不写入 |
| **P1 警告 + 方案** | 存量 | 输出偏离清单与建议名，等显式确认 |
| **P2 记录** | 建议级 | 只列不办 |

**安全红线**：校验器**不含任何改名或删除 API**——技术上无法自动改名，只输出报告与建议名。批量改名需人工逐条确认，单批 ≤10 项，改完复验。

## 安装

把整个目录放进技能库：

```bash
cp -r naming-convention_diy <你的技能库目录>/
```

或直接在对话中引用 `SKILL.md`。

## 文件结构

```
naming-convention_diy/
├── SKILL.md                        # 技能定义：范围、规则、澄清、校验、处置、触发
├── README.md
├── references/
│   ├── clarification.md            # 澄清规程（提问清单、决策树、边界、终止条件）
│   ├── scheme.md                   # 完整方案与词表（vocab-* 块为校验器词源）
│   └── current-state.md            # 一次真实扫描的现状数据（方案的证据基础）
└── scripts/
    └── check_name.py               # 命名校验器（纯标准库）
```

## 已知限制

- 只校验**名称形式**，不判断语义恰当性（`med-aaa-rev-v1.md` 形式合规但无意义）
- 领域前缀的最终选择依赖语义判断，工具只校验"是否属于合法词表"
- 不改名、不修复，只报告；建议名不检测引用关系
- 存量审计会产生大量 P1 偏离（原工作区 97% 目录无领域前缀），属预期结果，不应据此发起批量改名
