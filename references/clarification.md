# 澄清规程

调用本技能为任何对象命名时，**必须先完成澄清**，再产出名称。本文件是澄清的唯一操作规程。

---

## 一、为什么必须澄清

名称的四个字段里，只有一个是工具能安全推断的：

| 字段 | 可否从名称或上下文推断 | 说明 |
|---|---|---|
| 领域前缀 | ❌ **不可靠** | 取决于"交付对象与合规链"。同名关键词在不同场景归不同域（PDF-OCR 服务于医学名词提取 → `res-`；服务于合同解析 → `ops-`）。校验器只能给出"含领域推测，需人工确认"的猜测 |
| 用途中缀 | ❌ 不可 | 取决于处理阶段，名称里通常没有线索 |
| 主题 | ❌ **不可** | 必须由用户提供，工具不能编造 |
| 版本 / 状态 | ❌ 不可 | 取决于当前进度，只有用户知道 |

**结论：跳过澄清直接命名，等于让工具替用户做语义判断，必然产出错误名称。** 校验器的领域推测**只用于生成提问时的推荐项**，不得直接作为最终命名依据。

---

## 二、澄清规格（遵循本机既有约定）

- **一次抛出批量问题**，不要一问一答碎片化来回
- 单批次覆盖 **≥10 个信息点**（可用决策树收敛，不必逐条问满）
- **每道选择题的选项 ≤5 个**（领域有 7 类，故用决策树逐层缩小）
- 每题标注**推荐项**及理由
- **总轮次上限 50 轮**；若 3 轮内无法收敛 → 降级为"给出 2–3 个候选名 + 标注不确定字段"让用户直接挑
- 已明确的信息**不重复问**

---

## 三、第 1 批：定位与领域收敛（10 个信息点）

一次全部抛出，分支问题标注"视前面回答而定"。

| # | 问题 | 选项（≤5） | 作用 |
|---|---|---|---|
| 1 | 命名对象是什么 | 文件／目录／自建技能／一批文件 | 决定套哪套规则（技能名 vs 文件模板） |
| 2 | 新建还是改存量 | 新建／改存量 | 决定 P0 阻断还是 P1 报告 |
| 3 | 若改存量：是否被其他文件或文档引用过 | 是／否／不确定 | 引用风险，决定能否改名 |
| 4 | 是否交付给外部（机构、合作方、投资方） | 是／否 | 领域一级判定的入口 |
| 5 | 主要交付对象是谁 | 自己日常使用／临床或科研同行／基金或专利机构／外部合作方或投资方 | 领域一级 |
| 6 | 〔若选"临床或科研同行"〕内容涉及患者或临床数据，还是方法/证据结论 | 涉患者或临床／是方法与证据 | `med-` / `res-` |
| 7 | 〔若选"自己日常使用"〕是 AI 工具链资产，还是生活事务 | AI 工具链资产／生活事务 | `ai-` / `ops-` |
| 8 | 〔若选"基金或专利机构"〕是基金标书，还是专利事务 | 基金标书／专利事务 | `grant-` / `pat-` |
| 9 | 产物是给人读的，还是给机器/自己用的 | 给人读／给机器或自己用 | 用途分支 |
| 10 | 〔若"给人读"〕是调研结论／设计方案／正式成稿／演示 | 四选一 | `-rev-` `-dsgn-` `-doc-` `-sld-` |
| — | 〔若"给机器用"〕是脚本工具／数据集／图／原始素材 | 四选一 | `-tool-` `-data-` `-fig-` `-raw-` |

### 领域决策树（把 7 类压到 ≤5 选项/题）

```
Q5 交付对象
├─ 自己日常使用
│   ├─ AI 工具链资产（技能开发、模型调研、dsh、GitHub 同步） → ai-
│   └─ 生活事务（行程、通话转录、时间管理、环境排障）        → ops-
├─ 临床或科研同行
│   ├─ 涉患者或临床（干细胞管线、影像、患者数据集、临床方案） → med-
│   └─ 方法与证据结论（综述、Meta、文献检索、实验设计、绘图） → res-
├─ 基金或专利机构
│   ├─ 基金标书（齐鲁专项、国自然、尖兵计划）                 → grant-
│   └─ 专利事务（交底书、权利要求、检索查新、法律状态）       → pat-
└─ 外部合作方或投资方 → biz-（商业计划书、科学尽调、投资测算、房产投资）
```

### 领域仲裁规则（用户答"不确定"时用）

| 情形 | 归属 | 规则 |
|---|---|---|
| 房产调研（自住兼投资） | `biz-` | 涉金额决策与外部交易 → `biz-`；仅涉个人安排 → `ops-` |
| 影像处理脚本 | `med-` | 脚本跟随服务对象，不跟随技术栈 |
| 技能开发 vs 科研方法 | `ai-` vs `res-` | 产出是工具 → `ai-`；产出是结论 → `res-` |

### 用途决策树

```
Q9 用途
├─ 给人读
│   ├─ 调研与结论（调研报告、叙事综述、尽调结论）      → -rev-
│   ├─ 检索与证据（检索清单、参考文献验证、注册摘录）   → -lit-
│   ├─ 方案与设计（技术路线、实验设计、流程图）         → -dsgn-
│   ├─ 正式成稿（DOCX 终稿、通知书、合同、操作指引）     → -doc-
│   └─ 演示与汇报（PPT、汇报页、验收汇报）              → -sld-
└─ 给机器或自己用
    ├─ 脚本与工具（.py/.mjs/.ps1/.bat）                → -tool-
    ├─ 数据与数据集（影像、队列追踪表、结构化 JSON）     → -data-
    ├─ 图与视觉（示意图、路线图、封面、信息图）          → -fig-
    └─ 原始素材（录音、扫描件、来源网页、原始响应）      → -raw-
```

## 四、第 2 批：主题与后缀（3–4 问）

| # | 问题 | 说明 |
|---|---|---|
| 1 | 主题用什么词 | 自由文本。可给 2–3 个候选建议。支持中文（中文段内部可用 `_`），如 `761tel-ia`、`齐鲁制药专项_干细胞结合点` |
| 2 | 版本 | 首版（`-v1`）／第 N 版（`-vN`）／不加版本 |
| 3 | 状态 | 草稿（`-wip`）／待审（`-pre`）／定稿（`-final`）／归档（`-arch`） |
| 4 | 是否时间序列产物 | 是 → 追加 `-YYYYMMDD`；否 → 不写日期 |

**自建技能额外一问**：该技能是否为你自建（需以 `_diy` 结尾）？还是上游/第三方技能（保持原名）？

## 五、第 3 批：确认（必做）

给出**完整候选名**并**逐段回标来源**，再请用户确认：

```
候选：grant-qilu-2026-94-dsgn-wip.md
  grant-    ← Q5 交付对象=基金机构，Q8=基金标书
  -dsgn-    ← Q9/Q10 给基金方的技术路线方案
  qilu-2026-94  ← 第2批主题词
  -wip      ← 第2批状态=草稿
```

若涉及**改名存量**，确认项还需包含：

1. 受影响路径全清单
2. 引用风险判断（来自第1批第3问）
3. 单批 ≤10 项的限制说明
4. 需用户**显式回复"确认执行"**方可操作

## 六、澄清的边界（避免过度提问）

| 情形 | 处理 |
|---|---|
| 用户已一次性说清（如"给投资方写份商业计划书，初稿"） | 直接落 `biz-…-doc-wip`，**不再重复问已明确项**；仅确认主题词与版本号 |
| 用户答"你定" | 按仲裁规则给出唯一解，**标注依据**并声明这是推定 |
| 纯校验已有名称（用户只要"合不合规"） | 无需澄清，直接跑 `--name`。但若结论含"建议改名"且涉及领域推测 → **回头补问领域** |
| 一批文件批量命名 | 先问清是否同一领域与用途；混合批次则逐个确认 |
| 用户拒绝澄清 | 按已知信息出候选名，**明确标注哪些字段是推定**，并提示"确认后可一次改名" |

---

## 七、与校验器的衔接

```
澄清（本文件）
   ↓  拿到 领域/用途/主题/版本状态 四项确定值
拼名（SKILL.md §2 模板）
   ↓
形式校验：check_name.py --name "<候选名>"
   ↓  退出码 0 → 交付；1 → 按违规项回改
交付时回标：每段来自哪一问（便于用户复核）
```

**硬规则：`check_name.py` 输出的"含领域推测，需人工确认"标记，是提问的信号，不是命名的依据。** 见到该标记即回到第 1 批 Q5–Q8 向用户确认领域。
